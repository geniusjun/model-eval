# AGENTS.md

model-eval checks whether an LLM service still follows its prompt rules after a model swap.
Read this before changing anything.

## Read first

1. `.specify/memory/constitution.md`. It overrides every other convention here.
2. The feature you are touching under `specs/NNN-name/`: `spec.md`, `plan.md`, `data-model.md`,
   `tasks.md`, then `contracts/`. `data-model.md` and the contracts define behaviour, and code
   follows them.
3. New behaviour goes into the spec first, then a failing test, then code.

## Layout

- `src/`: library and CLI
- `viewer/`: result page (React)
- `schemas/`: generated by `pnpm schemas`, never edited by hand
- `test/`: `unit`, `contract`, `e2e`, `viewer`, `browser`
- `examples/pogo/`: synthetic demo service
- `docs/`: user guides and reference

## Commands

```bash
pnpm install
pnpm typecheck && pnpm lint && pnpm format:check
pnpm test              # builds, then unit, contract, e2e and viewer tests
pnpm check:coverage    # every FR of an In Progress or Implemented spec has a test
pnpm bench             # statistics simulation, run by CI
pnpm test:browser      # after pnpm build and pnpm exec playwright install
```

The Python helper in `adapters/python/`. Its tests run in an environment built from one file of
`tests/requirements/`. The contract tests of `pnpm test` start Python from `MODEL_EVAL_PYTHON`,
an interpreter with both SDKs; CI builds it from `openai-2.txt` and `anthropic-2.txt`.

CI on a pull request runs the helper tests on the lowest and the newest supported runtime:
`openai-2.txt` and `anthropic-0.txt` on Python 3.10, `openai-3.txt`, `anthropic-2.txt` and
`both-transports.txt` on the newest Python; Node 22 with the first supported release of each
Node SDK and Node 26 with the newest. A push to main runs every file on Python 3.10 and the
newest Python (`openai-1.txt` on 3.13, which openai 1.x does not go past), and Node 22, 24 and
26 with every Node SDK alias on Node 22. Before merging a change to a helper, run that full set
on the branch: `gh workflow run ci.yml --ref <branch>`.

```bash
cd adapters/python
uv venv --python 3.10 .venv
uv pip install --python .venv/bin/python -r tests/requirements/openai-2.txt
MODEL_EVAL_REQUIREMENTS=openai-2 .venv/bin/python -m pytest -n 4
uvx --python 3.10 --with pytest --with httpx2 mypy --strict --python-version 3.10 \
  --exclude 'tests/services/py311_' tests model_eval_adapter.py
uvx --python 3.11 --with pytest --with httpx2 mypy --strict --python-version 3.11 \
  tests model_eval_adapter.py
uvx ruff check && uvx ruff format --check
uvx ruff check --target-version py311 tests/services/py311_*.py
```

## Rules

- A test for a requirement names the feature number and FR ID: `it('001 FR-007 ...')`. Skipped
  and todo tests do not count.
- Real user conversations, API keys and production data never enter the repository. Examples
  use the synthetic pogo service.
- Docs describe the current behaviour only.
- Commit messages: `type(NNN): short title` and a line `Tasks: T043-T049` for feature work;
  `type: short title` for anything else.
